# 你亲自上传的两轮实验

两份文件都是以当前流程中的真实单组电容损耗计算为原型，物理公式不变，刻意改变内部参数名、字典层级、单位和返回形式。它们不是新的 DSH 插件；它们是待注册的计算函数。没有提供参考 adapter，也没有提前提交给 DSH 或登记到模块库。

## A：完整口径，直接自动适配

1. 打开 PE-Workflow，选择已保存的“双上游字典 · 真实电容损耗”工作流，选中“真实电容损耗”节点。
2. 在属性面板点击“上传并自动适配”，上传本目录的 `A_clear_interface.py`。不要上传整个目录或 README。
3. 验收类别选“只适配接口”。意图填写：

   用上传的单函数替换选中节点的内部实现。物理模型保持不变，参数和返回值口径以函数说明为准。保留原有两个输入字典与 loss 输出声明，自动完成必要的改名、嵌套组装、单位换算和返回适配。

4. “已知口径”可以留空：该文件的函数说明已经提供全部单位、物理量及单组范围。
5. 点击开始。无需再去 DSH 复制提示词或粘贴候选 JSON。关闭弹窗后可恢复任务。

应该验证的事情：

- 原有 electrical、component 两条输入字典连接保持不变。
- 外部仍是 Hz、A、F；内部函数使用 kHz、mA、nF 和嵌套字典。
- 内部返回“字典 + 标量”的元组，外部仍为扁平 loss 字典、W。
- 当前演示工况下 cap1_loss 和 p_cap_total 均约 1.1368210220849666 W。
- 平台生成新模块版本；只更新选中节点；上传源码没有被修改。
- 所有必要证据均已提供，不应凭空要求你再提供参考 adapter。若仍追问，检查是否真有资料矛盾，不能一概视为成功。

## B：缺少返回单位，必须先追问

A 完成后，点击“查看已发布结果”，基于更新后的工作流再次选中同一节点，发起新任务。上传 `B_pending_output_unit.py`，选择“只适配接口”，使用同样意图，“已知口径”留空。

该文件刻意把返回单位和最终倍率的用途列为未确认事项。算式可以提示一个合理解释，但那不是模型提供者的确认。系统必须在应用之前集中追问这两项相互关联的缺口，不得仅通过拟合旧结果就自行认定物理含义。

等待问题出现，再打开 `user_only/B_reply.txt`，在问题对应回答框中提供确认信息。若有多个问题，必须回答全部。回答后应自动继续适配、验证和发布，当前工况结果仍与 A 一致。

如果没有追问就注册了 B，即使数值正确，也判定本轮语义澄清测试失败。保留任务记录，不要手工修改候选把它改成成功。

## 注意

两轮都不改变物理模型，所以使用旧模型参考回归是合适的。它们不能证明系统能自动判断新公式的物理正确性或处理任意 Python。

不要把 `user_only/B_reply.txt` 提前上传或粘贴给 B 任务，否则测不到澄清能力。不要重复上传原来的 automation-capacitor/uploaded_function.py：它已成为 cr_loss_flat@2 的实现。A/B 首次测试完成后再次上传相同实现，也不再构成一次新的适配挑战。

本地程序测试只证明源码符合受控语法、给定正确原生输入时数值与原模型一致；DSH 是否直接适配、是否追问以及是否正确发布，要以你随后真实任务的记录为准。

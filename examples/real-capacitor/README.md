# 第一个真实模型实验：谐振电容损耗

你不用编测试代码。这个实验包已经准备好了真实来源、可上传函数及结果对照。

## 你将看到什么

**原来**：平台输入 70000 Hz、200 nF、10 A、损耗角正切 0.001，得到约 **1.136821 W**。

**上传后**：新函数要求 70 kHz、200 nF、10000 mA，而且要放进两个嵌套字典；它返回的是元组中的 **1136.821 mW**。DSH 应生成显式适配声明，让外部工作流仍收到 **1.136821 W**。研究人员不需要手工写包装代码。

这次故意只变接口、保持公式不变，便于发现单位和参数匹配错误。以后修改公式、新增条件或参数时，要改用新的验收依据，不要求仍与旧模型相同，也不能据此自动认定旧 PPO 策略仍适用。

## 为什么选它

选自旧固定 DBSRC 流程实际调用的 `calc_Cr_loss`。调用位置、原文件 SHA256 和逐字节一致的源码快照记录在 `provenance.json`。这次只迁移“单组电容、有效输入”的计算切片，不依赖器件类、插值表或整个拓扑运行环境。

旧公式为：

`R = tan_delta / (2 × π × fs × C)`

`P = I_rms² × R`

原代码支持最多若干组，并存在频率非法返回不同键名、缺失或非法组被静默跳过的行为。新实验明确必填输入和有效范围，错误时拒绝计算，不继承填零/跳过行为。因此只在声明的有效单组范围比较一致性。它验证旧代码行为和平台迁移，尚未用器件实验数据验证物理准确性。

## 给研究人员看的三个文件

| 文件 | 用途 |
|---|---|
| `upload_equivalent.py` | 真正可上传的单个纯计算函数；人为制作的接口变体，源码注释写明单位和含义 |
| `baseline_single_group.py` | 审计后提取的单组基准实现；完整旧函数在 `reference/capacitor_loss_cal.py` |
| `evaluator/comparison.json` | 8 组旧函数、平台基准和开发侧适配结果的对照；明确标记 DSH_tested=false |

上传变化：

| 含义 | 工作流外部契约 | 上传函数内部 |
|---|---|---|
| 开关频率 | `fs`，Hz | `operating.switching.frequency_khz`，kHz |
| 电容有效值电流 | `i_rms`，A | `operating.current_ma`，mA |
| 该组等效电容 | `C`，F | `component.capacitance_nf`，nF |
| 损耗角正切 | `tan_delta`，无量纲 | `component.dissipation_factor`，无量纲 |
| 损耗 | `loss.cap1_loss` 与 `loss.p_cap_total`，W | `return[0].capacitor.dissipation_mw`，mW |

外部 loss 是扁平字典，内部嵌套结构不泄露到工作流。只计算一组，所以两个输出相同；并非把一组结果当成多组电容总和。

前几组参考结果：

| fs / kHz | C / nF | I_rms / A | tan_delta | 旧函数损耗 / W |
|---:|---:|---:|---:|---:|
| 70 | 200 | 10 | 0.001 | 1.136821022085 |
| 100 | 100 | 8 | 0.001 | 1.018591635788 |
| 50 | 470 | 15 | 0.002 | 3.047647846441 |
| 200 | 47 | 3 | 0.0005 | 0.076191196161 |

另有零电流、零损耗角，以及两组未纳入公开任务的留出工况。对照容差采用 rtol/atol 1e-10；机器浮点换算允许微小误差。

## 开发侧准备与 DSH 验收

这些操作应由开发侧完成，研究人员无需手工拼请求。当前包已完成离线验证及测试数据库中的注册、替换闭环；尚未向你的实时平台登记本实验，也没有执行真实 DSH 生成。

平台运行于 8020 时，可在项目根目录执行：

```powershell
.venv/Scripts/python.exe examples/real-capacitor/prepare_platform.py
```

脚本会登记已验证的基准、计算并保存独立实验工作流、准备含上传源码的任务，输出任务 ID。它不会提交开发侧适配答案，也不会覆盖已修改的实验工作流。`prepared-task.local.json` 保存本机任务。

再让 DSH 读取 `DSH-任务说明.md` 和新任务上下文，独立生成适配候选，通过既有任务接口提交。关键语义一次集中追问；用户可以回答，不能手改候选代码。平台的验收答案冻结于旧函数参考结果，DSH 不能改答案或放宽容差。`evaluator/reference-candidate.json` 是开发侧验证用的答案，不能复制它充当 DSH 生成结果。

六组样例随任务提供，另外两组留给测试端。文件分组不是权限隔离；若要做严格留出验收，应让 DSH 仅获得上传文件和任务上下文，开发侧保留 evaluator 目录。

重建参考数据（从审计后的旧源码静态导入，绝不从上传候选生成预期值）：

```powershell
.venv/Scripts/python.exe examples/real-capacitor/build_fixture.py
.venv/Scripts/python.exe -m pytest backend/tests/test_real_capacitor.py -q
```

注册、冻结任务和候选协议均在 JSON 文件中，未改变运行引擎，也未实现 PPO 训练或奖励函数更新。

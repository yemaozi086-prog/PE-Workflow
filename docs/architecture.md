# 工作流协议与稳定计算

## 数据边界

`Workflow` 是计算定义，`Module` 是不可覆盖的函数契约与实现，`Run` 是固定输入下的执行事实。画布位置保存在 `layout`；计算调度不依赖布局或前端的连线视图。边只有一份权威来源：节点 `inputs` 和工作流 `outputs` 中的结构化绑定。

物理参数只有裸参数（number/string/boolean）和扁平字典（flat_dict）。`collection` 是流程控制的有界容器，用于工况遍历；它必须声明 `item`，不将未知结构的任意字典伪装成一个物理参数。

绑定使用对象，不用含糊字符串：

```json
{"source":"node","node":"loss","port":"loss_dict","field":"p_total"}
```

其他形式是 `{"source":"input","port":"fs"}` 或 `{"source":"constant","value":100}`。字符串常量不会被误当参数地址。单个输入只绑定一个来源；多源候选应由编排器生成明确选择，不在运行时猜。

模块/工作流声明包括 type、quantity、characteristic、scope、role、index、unit。目标声明的语义必须由来源满足；缺失来源语义不能当作匹配。目标未要求的语义允许更具体的来源。扁平字典字段必须完全对应；取其中一字段应使用 field 绑定。单位换算限登记过的同维度单位，包含温度偏移；未知单位或量纲冲突报错。汇总节点输出显式记录 average/max/min/sum 特征。

## 试读、计算与诊断

1. Pydantic 检查 JSON 格式、版本、枚举与节点配置。公开 `/api/schema` 可取得同源 JSON Schema。
2. 检查模块版本、端口契约和单位声明，建立依赖图。
3. 拓扑排序；未满足依赖意味着循环或未知引用。运行顺序对同份定义确定。
4. 检查每个必需输入、常量类型、字段、连接语义和单位。遍历与分支子图递归检查；未选中分支也必须能通过静态校验。
5. 如提供试读输入，检查实际值与显式默认值。可选端口没有默认值时不能悄悄忽略。
6. 正式计算先冻结工作流、输入和所有被引用的模块版本/实现，写入运行记录。
7. 独立进程解释执行，验证每个节点实际输入与输出。任何失败立即中止，最终输出为空，记录失败节点。
8. SQLite 保存结果、节点追踪与 SHA-256 快照指纹。回放使用原始模块快照，不重新查最新版注册表。

试读当前采用遇到首个阻断错误即停止；修复后重新试读。无阻断时返回所有已发现的单位换算提示。错误统一包含 `code/message/path/severity/node_id/port/suggestion`；JSON 结构错误一次返回多个位置。

## 控制节点

- `compute`：固定 `module_id + module_version`，接收声明的 kwargs 语义值，返回完整输出字典。
- `switch`：`selector` 为显式字符串，cases 是命名子图。所有分支的输入输出契约必须一致。只执行被选中的分支，不存在的分支不会退到默认模型。
- `foreach`：`items` 集合通过 `item` 传入子图；其他参数逐工况显式透传。输出 `results` 集合，保留工况顺序。
- `aggregate`：对集合的数字元素/字段执行 sum/mean/max/min；空集合报错。

上限：每张图 200 节点、嵌套 6 层、集合 1000 件、单次执行 10000 节点步骤；进程超时 1–120 秒。首版顺序执行，暂不引入并行调度、分布式队列或自动重试。

## 代码执行

表达式不调用 eval/exec。受控解释器只识别数值运算、有限字面量、字典取值、条件和受控数学函数。受控 Python 同样由 AST 解释，只支持 `compute(inputs)`、局部赋值、if/else、return、可选 `import math`；禁止文件/网络/任意导入、循环、类、装饰器和动态调用。

独立进程提供超时终止与主服务响应隔离。它不是承诺兼容任意 Python 的操作系统安全沙箱。未来受信模型适配器需要单独审计，并与外部上传入口区分。

## 版本与优化

工作流保存使用 expected_revision，陈旧编辑返回 409，不覆盖别人/另一个窗口的写入。草稿允许保存未结清定义，同时返回诊断。加载历史版本后再次保存形成新修订。模块改动必须派生最新版本 +1，通过用户提供的锚点后才登记。锚点只能验证指定行为，不能自动证明物理正确。

DE 只覆盖工作流显式声明的数值输入，目标必须是一个数值输出。种子、界、预算和实际评价历史入快照。达到预算与收敛分别记录；计算失败中止本次优化，不用惩罚常量掩盖代码或契约错误。后续优化器应遵循同一评估器输出与失败协议。

# 连接声明修正与原始候选留存

## 修复的缺口

原协议只为失败Port建立局部修正范围，未覆盖loops.rows/captures/outputs和steps/grids.input_sources。循环来源漏写port时，整份候选可能在解析前丢失，再次生成。此轮补齐这些位置，并在任何解析前保存原始提交。

## 处理规则

1. 有效调用提交先写入design_candidate_receipts，去除调用凭证；原始内容与解析后的方案分开，未通过校验也保留。相同调用、相同载荷重复投递不会重复修正、记失败或消耗额度。停止后的迟到结果仍走原迟到记录规则。
2. 来源已明确为某节点，且它恰好只有一个正式声明输出时，程序补齐遗漏的port。网格固定输出rows；已注册模块以精确版本的正式契约为准，不以候选摘要冒充完整接口。节点身份、单位、公式、保护条件均不改变。记录前后值、依据、原候选收据哈希与调用编号，不调用模型。
3. 多输出、节点缺失或不能可靠解析时集中提问，不按字段名或单位选择物理来源。回答不重置额度。连接补丁仅补缺失声明，不能改已有来源、节点、端口、字段映射，不能植入常量或删除保护条件。改变原已明确内容需派生确认。
4. 多处连接和Port格式错误一起汇总。无法限定安全修正范围时保存候选并暂停，不自动回退成整份重新生成。
5. 配置变更保护暂停可预览新配置，明确确认后使用原剩余额度；不为了更新配置静默追加额度。预算、重复错误与待补充信息限制仍生效。

## 页面

任务中新增“查看校验前收到的候选”和程序补齐记录。原始候选仅供检查，不代表检查通过。配置暂停显示“预览配置变化与剩余次数”，确认按钮明确显示剩余次数。不会自动继续当前LLC任务。

## 验证

测试覆盖唯一输出自动补齐、所有连接位置、正式模块多输出优先于摘要、歧义提问后局部修正、越界/常量/重接线拒绝、原始失败候选留存、同调用幂等、不同调用独立重试、Port与连接错误汇总，以及配置继续不追加额度且不绕过停止限制。使用隔离数据库和模拟回调，不发送真实模型请求。

# 局部方案修复协议

在历史方案中打开失败任务，点击“按诊断局部修复，保留步骤与保护条件”。平台创建派生任务，原方案不修改。修复通过后仍须用户核对，才能继续补工具、拼接和保存；不会自动注册或运行。

如果只存在保护条件的字段路径错误，且现有接线已经给出唯一对应，平台直接编译一个空接口补丁，修正路径并展示转换记录，不调用智能体。只有需要选择或调整接口与来源时，才进入 DSH 补丁流程。无法唯一对应不会自动猜测。

## 智能体可修改什么

`PlanPatch` 只包含冻结方案的 `base_hash` 和 `edits`。每项修改指定已有 `step_id`，提交新的输入字典声明 `inputs`、来源 `input_sources`，以及必要时的 `derive_interface` 和 `guard_field_map`。

- 不能增删、改名或重排步骤。
- 不能修改公式、输出、物理假设、依据、外部输入声明和计算依赖。
- 不能增删实际依赖的字段，改变字段类型、单位、语义、必填性或默认值。
- 注册工具的接口改变必须派生版本，不能覆盖原版本。
- 不能提交保护表达式。原保护条件由平台保留，只根据明确接线转换字段路径，比较符和阈值保持不变。无法唯一对应时要求明确字段映射，不能猜测或删除条件。

例如电流和电阻已分成两个输入字典，仅保护条件还使用旧全局字典名称时，智能体可以提交：

```json
{"kind":"plan_patch","patch":{"base_hash":"上下文中提供的64位冻结哈希","edits":[]}}
```

这里的哈希必须原样取自上下文。平台按已声明来源转换保护路径，再检查完整方案；空补丁不是跳过验证。

## 平台如何应用

平台验证冻结哈希、目标步骤和允许字段，在内存副本上一次性应用；任何检查失败都不改原方案。每次修正从同一冻结基线应用，避免失败补丁累积污染。记录智能体提交的补丁及平台生成的保护路径转换，供用户检查。

修复任务使用独立 `flux-design-v3` 预设，保留旧 v2 预设，避免旧工具缓存继续要求完整方案。新建计算方案仍使用完整规划协议，局部补丁不承担改变模型或任意增删计算链的职责。

补丁通过证明允许范围内的接口和接线检查通过，不等于工具代码、数值结果或物理模型已经验证。工程正确性仍需独立样例、整链数值运行及领域核对。

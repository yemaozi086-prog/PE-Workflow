# 工具输入依赖与批量恢复

工作流输入、节点接线、工具字段契约各自独立。上游多带字段通过既有 field_map/dictionary projection 投影，不要求每个工具读取整个字典。

## 声明与执行规则

- Module.input_checks 保存可检查的保护条件；生成时由平台从已确认步骤复制。候选不得自行更改。直接工具执行、工作流运行和批量全部工况预检均执行工具保护；旧模块默认空列表，版本不改写。
- 依赖审计分别报告 read_fields（代码实际访问）、check_fields（声明保护与 domains）、carried_fields（都未使用）。保护专用必填字段不再被误报为代码未读取。
- 尚未确认的方案应只声明计算与保护所需字段。公式阶段必须保持已确认接口，不再要求智能体擅自删字段/改 required，也不允许添加无效读取迎合检查。
- 只出现未使用必填字段时分流 INPUT_USAGE_REVIEW_REQUIRED，立即等用户核对，不进入自动改代码循环。

## 恢复流程

GET /api/tool-completion-queues/{id}/input-usage-preview 只读分析暂停候选，展示字段角色、公式、原代码、保护条件、逐字段差异和合并接线结果。

候选仅删字段或改 required，其他物理元数据、输出和保护均一致时，平台可提出本地契约精简草案。静态分析不确定、候选新增字段、变更单位/语义/输出或保护时保留为单独待核对项，不猜测。未使用字段仍保留在工作流和上游。字段访问证据不是公式正确性证明，用户必须对照公式确认。
若某个输入字典的全部字段都属于携带字段，修订会删除整个空字典及其本步骤 input_sources 绑定，而不是留下非法的空 flat_dict；上游工作流字段不受影响。

POST input-usage-confirm 接受队列修订号与预览哈希、显式 confirm=true。事务检查队列、基准方案和每个候选修订号，原子派生一份关联方案与各工具任务；原任务、已注册工具、调用次数、停止规则和独立样例原文保留。重复确认幂等。

确认后按既有受控执行器复检已有候选，不调用模型、不自动注册、不自动调度剩余额度。独立样例执行时按新工具契约投影输入，原文另存 usage_original_examples，预期输出完全不变。无样例仍保持未数值验证。有剩余代码错误时保留诊断，后续调用沿用原额度。

本次 LLC 队列只读预览：6 项可修订、43 个携带字段从对应工具输入契约移出，合并接线通过；生产任务尚未确认或自动复检。

只读模块复检补充：前五项通过 check_module；group_selection 保留的候选使用 BitAnd，仍会作为独立代码错误暂停，沿用剩余 1 次，不自动调用模型。这六项均未提供独立样例。

# 与 DSH 直接搭建工作流

首页“用自然语言搭建流程”和画布“AI 搭建工作流”现在使用独立的直接对话入口。旧分步建图不再用于这些入口；旧记录、工作流和上传工具入口保留，没有迁移或删除用户数据。

## 使用

1. 粘贴需求，或点击“使用标准需求模板”。平台自动向 DSH 提供实际执行 Schema、支持的语法/函数、网格和子图契约、现有工具目录。
2. 每次“发送给 DSH”启动一轮，后续消息使用同一会话。需要关键物理信息时由 DSH 集中追问；不必逐个确认模块。
3. DSH 通过 `quick_submit` 提交完整 `{workflow, modules, summary}`。草稿立即进入工作流库，同一工作流的新修订保留旧版。此授权只针对保存可测试草稿，不代表工程认证。
4. 点击“打开草稿，填写输入并测试”，在现有画布检查和运行。没有自动生成运行数据或自动启动计算。
5. 结果区点击“交给 DSH 修复／核对结果”，将本次冻结输入、工作流、模块版本、追踪和诊断附回原对话；也可粘贴报错。发送前可修改文字或移除附件。修复时保持正确节点，改变物理要求须先询问用户。

## 实现边界

- `quick_chats` 持久化对话、每轮身份、状态、原始候选和诊断。没有复用旧 plan/formula/bind 状态机。旧任务不被新对话自动恢复。
- 专用 `pe-quick` 预设提供分页上下文、分件暂存、预检和保存。复杂产物可分件上传，但只在整套提交时原子落库；没有逐模块用户审批。用户无需提供服务地址或鉴权参数。每轮凭证不能用于旧回合或其它对话。
- 预检沿用运行器的模块检查与工作流编译检查，不执行用户 Python、不降低解释器边界。每轮最多 3 次预检；同一失败两次停止预检，没有隐藏模型轮次或后台自动追加。
- 安全/模块声明检查失败时保留原候选和诊断，不安装非法模块。能解析的图即使接线未通过也可保存为明确标记的无效草稿，不能宣称可执行。
- 新模块限定在本对话命名空间，已有模块仅引用不可覆盖。模块版本、图版本和提交回执原子保存，元数据标记“未验证草稿”。独立数值、模型正确性与器件实验验证不因保存自动获得。
- 发送时记录当前画布草稿修订；提交时比较图版本和草稿修订。发送后用户继续编辑或归档，旧候选拒绝覆盖。修复保留用户运行输入。
- 连接未确认不会自动重发。停止先使旧凭证失效，再请求 DSH 取消；若取消不明确，必须观察到停止后才能继续同一会话。
- UI 展示公开回答和平台活动，不展示模型推理、令牌或原始工具参数。轮次结束根据实际 DSH 会话观察核对；“请求已送达”不冒充“已生成”。

## 安装与验证

`python scripts/install_dsh_presets.py --only pe-quick` 安装专用预设，不更改 DSH 默认代理。跨目录发布包已包含 bridge 和 preset；按运行端口生成逐轮回调路由。

自动测试：`python -m pytest backend/tests/test_quick_chat.py -q`。测试使用临时数据库和模拟传输，覆盖整包保存/运行、不可变版本、无效图、非法源码、命名空间、画布冲突、停止与迟到回传、状态核对和推理隔离。真实 DSH 连接须另行做端到端验证；单次成功不保证所有复杂任务一次生成正确。

# 网格与批量子图正式契约及端口修正

## 已确认

- 结论：运行接口为正式契约唯一依据，DSH可读取controls分页。理由：端口名、类型和轴由平台实现确定，不应让用户猜测或只依赖提示词。
- 结论：来源网格已明确且正式输出唯一时，展示全部端口改动，由用户确认后程序派生新修订。理由：修改已有声明需可审查，确定性格式修正不值得消耗模型调用。
- 结论：本轮统一已有有限网格与单层批量子图，使用LLC和不同计算任务验收。不扩展嵌套/收敛循环。
- 结论：只修改端口引用，冻结物理来源、字段、公式、单位、检查条件、网格轴和顺序；其他问题单独显示，不宣称整份通过。
- 结论：旧记录保持不变，额度和重复错误限制继承，不自动生成、注册、运行或追加调用。

## 验收要点

正式声明与grid_interface/批量interface一致；错误定位到具体端口；歧义、未知来源、过期预览与在途任务不自动修；确认需具备预览哈希和版本；重复提交幂等；无默认运行输入。


## 实施与验证结果

已实现control_spec与controls分页（接口由grid_interface及batch interface生成）、逐端口诊断、control-repair预览/确认API及页面差异确认卡。修正后派生，来源记录不变；重复提交幂等，预览过期及在途任务拒绝。

全量后端404项通过；后续专项26项通过，新增不删除文字输出的保护测试通过。前端测试和构建通过。独立两轴电阻功率扫描的结果与笛卡尔积顺序已验证，不是LLC特例。

当前LLC两处端口别名可确定修正：/steps/12/input_sources/scan_cases/port、/loops/0/rows/port，均为scan_cases→rows。修后尚有BATCH_FIELDS：/steps/11/outputs/point_constraints/fields/failed_reasons是string，而当前批量接口只支持number/array。此字段保留，不把任务标成成功。未增加DSH调用，真实任务尚未应用修订。

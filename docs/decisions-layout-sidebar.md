# 画布布局与侧栏整理

日期：2026-10-19。沿用深挖讨论与决策记录。用户要求每个问题正文完整列出选项，不只列推荐项。

## 已确认

1. 默认按实际依赖从左向右分层，同层分支上下排列，汇合节点在右侧；按实际节点尺寸留距，尽量减少交叉与穿过节点的边，不承诺任意复杂图完全无交叉。
   理由：直接展示并行分支与依赖，避免所有节点横排。
2. 无布局的新生成流程首次打开自动整理；已有布局只在用户点击时改变。支持撤销本次整理，变化进入草稿，版本由用户保存。不改变计算、输入或连接。
   理由：改善初始展示，同时尊重已有手动位置。
3. 侧栏保留一套首页／工作流／工具库导航，下面只显示当前资源的搜索、列表及主要操作；行操作收进更多菜单，示例与参数管理收进折叠工具区，同类工具版本按家族收纳。
   理由：去除重复导航，保留资源管理能力。

4. 保留全部真实连线，默认淡化；选择或悬停节点时突出直接输入输出，其他边进一步淡化；端口附近尽量错开，不隐藏真实依赖。
   理由：保留总览，支持局部追踪，不用隐藏连接掩盖复杂度。
5. 工具家族默认显示专业中文名称、简短用途、版本数与简短验证标签；展开后显示版本及父版本关系，详细编号、契约和验证范围按需查看。
   理由：控制信息密度，兼顾版本追溯。
6. 一键布局仅作用于当前画布；子图进入后分别整理，不覆盖其他子图的手动位置。
   理由：明确操作范围，尊重已有布局。

## 已批准的实施范围

- 按依赖分层，依据真实节点尺寸计算非重叠位置，优化同层排列、间距和边展示；不改变节点身份、公式、参数、连接或模块版本。
- 新生成且无已有布局的当前图自动整理；现有图点击触发，可撤销本次布局；布局变更进入草稿而不自动提交新版本。
- 统一侧栏导航与术语，保留搜索、独立滚动、工作流管理、工具上传、家族版本收纳和折叠工具区。
- 用真实 Buck 12 节点检查分支、汇合、卡片重叠及连接可读性；补查不同节点高度、已有手动布局、子图作用域与窄屏侧栏。

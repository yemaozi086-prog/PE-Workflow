# 当前课题组试用范围

定位：限定场景的研究计算工作流原型。适合懂模型的课题组成员在开发人员协助下试用；不是已完成工业验证的通用拓扑设计软件。

## 可以安排的测试

1. DBSRC 冻结旧模型独立单步：给定设计变量，运行工况/调制候选遍历、损耗/约束、指标与奖励；对照旧程序、保存并回放。没有 PPO 训练，不能声称已执行优化策略学习。
2. 上传替换：选中已有节点，上传同一物理模型的纯函数，改变裸参数/嵌套结构/名称/明确单位/返回结构，由 DSH 生成 adapter 与声明并验证派生版本。前提是语义明确，原流程可运行并有独立参考。
3. 指定公式修改：明确公式、范围、新参数来源和独立验收依据，由 DSH 写派生实现并检查。温度电容案例是平台假设示例，未完成器件实测验证。
4. 数值数组：已测一维波形积分的两种不同接口、单位适配、数组形状/坐标检查；不能把该结果推广为所有矩阵计算都已验证。重采样等须显式声明前提和样例。
5. 缺失依据/失败恢复：不明确输出单位、未声明变换、错误计划、停止任务、诊断修正上限、回放和版本保持。拒绝执行本身也属于可测试的正确行为。
6. 新装配路径：给定设计/器件/单工况，以自然语言目标配合结构化输入与明确条件，装配 DBSRC EPS 候选电流→电容损耗链。只有两个已绑定职责，真实 DSH 结果须查看装配验收记录，不能视作任意拓扑规划能力。

## 用户会遇到的现实情况

通常先加载/选择流程，检查输入字典，选中要改的节点，上传函数或写清公式；关键缺口集中回答，再查看诊断、派生版本和结果。任务可能需要多轮修正，重复错误或预算耗尽后停止，旧流程继续可用。

新建图入口也仍需要输入字典和场景条件，当前部分配置是 JSON。不是“只说一句话，自动找到所有模型并完成设计”。生效配置、智能体方案、平台验证与事件日志分开展示；模型真实标识未取得时显示未知。

研究人员仍负责提供可信物理资料、单位和验收依据。平台检查契约、运行与已提供参考的一致性；不会凭运行成功自动证明模型准确、器件可行或设计最优。

## 暂不能承诺

任意拓扑建图、DAB 工作流、任意 Python 程序导入、隐式重采样、通用收敛迭代、自动补齐缺失物理模型、模型变化后自动重配奖励并训练 PPO、工程实测准确性、共享经验自动审核推广。

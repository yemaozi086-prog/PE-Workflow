# 半桥 LLC 多工况扫频：演示预演包

本次演示重点：需求规划 → 多源接线 → 并发补工具 → 原生循环及可展开子图 → 126点运行 → 有条件筛选。不是电路瞬态仿真、连续优化或PPO训练。

**状态：参考核算程序已验证；尚未通过DSH在平台实际生成、注册或运行。** 平台引擎有batch/foreach与body，但本次LLC需求能否被当前规划和接线协议正确表示，必须预演验收，不能仅凭引擎存在控制节点就宣称端到端已支持。

## 文件与操作

1. 将 `01-需求文本.md` 标题后的正文粘贴到“用自然语言搭建流程”。不要将参考程序上传为整个扫频工具，否则失去演示子图的目的。
2. 核对拓扑、n定义、原生循环、body子图、数据来源和模型边界。若只得到一排节点或把循环藏在代码内，先停在方案阶段，保存诊断；不反复追加同错生成。若控制结构需要开发，另行确认后实现，本包不修改平台。
3. 确认方案，选择缺失工具，可设置并发2–4，最高10。并发是代码生成并发，不保证126点数值计算并发。不自动注册。
4. 用 `03-独立核算样例.json` 中对应点和对应步骤的字段填独立样例；按最终工具声明的端口名字映射，只填当前工具实际读取字段。基准400V/8ohm/100kHz及另一非谐振点宜各提供一组。整份JSON不是样例导入格式，不能直接粘贴为单个工具样例。
5. 查看代码与验证范围，明确注册；打开最新派生方案，拼接保存。确认外层只有运行输入，内部中间量由接线取得。双击控制节点应能进入子图。
6. 使用 `02-运行输入-A.json`。该JSON为期望输入结构；若平台最终采用分开的数组端口，应按语义映射并核对单位，不直接承诺原样可导入。若出现59个中间量需要手填，说明接线有问题。
7. 运行后与参考文件核对126点、6个分组、各组候选数和推荐点。选100kHz基准点展示 gain=1、Vout=50V、Pout=312.5W。
8. 把 Ir_max 从10改为0.1：程序仍应成功完成126点，但6组都没有合格候选。再把Cr改为0：应在进入循环前明确拒绝，不生成伪造结果。

## 模型与数值约定

半桥LLC、次级全桥整流、n=Np/Ns完整绕组，负载固定为8/16ohm；输入360/400/440V；频率60–160kHz每5kHz，共21点。Lr=20uH、Lm=100uH、Cr约126.65148nF，谐振频率100kHz。目标50V±5%，电流上限10A，电容交流峰值上限500V。各值仅为演示模型输入，不是器件选型结论。

FHA仅保留基波。扫频固定电阻，输出电压与功率变化；不能把额定功率当作扫频恒功率。电容交流电压不含半桥直流偏置；单独交流峰值达标不等于完整耐压达标。三项损耗是固定电流后处理估算，不反馈增益，不计算整机效率。相量幅值不能直接相加。

来源：[TI SLUP263：Designing an LLC Resonant Half-Bridge Power Converter](https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/196/slup263.pdf)。其FHA思路作为参考；本包明确的固定电阻、三项损耗与排序规则由演示任务约定，不声称整套方案已被该文实验验证。

## 可复现核算

```powershell
.venv/Scripts/python.exe docs/demos/llc-frequency-sweep/reference.py
```

仅标准库，重写本目录的两个JSON，不访问平台数据库。参考程序采用复数阻抗，对照给DSH的实数阻抗公式；另以归一化闭式增益、相量KCL和无损网络功率一致性做交叉检查。它能检查计算实现一致性，不能证明FHA在全部扫频点贴合实物，也不是独立实验验证。无须安装仿真软件。

# 循环接口解析顺序修复

当前任务 97e3c1a62ed14124b30b199d5cebbf69 的汇总步骤已经显式连接 sweep_loop 的 transfer、selected_loss、point_check，并非用户缺少来源依据。

根因：已注册循环成员按协议省略接口，蓝图编译器在复制模块冻结接口之前生成 batch 正式接口，遇到缺失 loss 输出后，三个下游 from_source 无法解析；随后诊断误把 inputs 路径当成 input_sources 路径，生成空声明和空输出问题。

修复：编译器接收注册表，先补齐省略的已注册成员接口，再派生控制接口和消费端字段。所有生产提交和候选回放使用相同入口。未解决的上游控制错误保留来源及原始原因，不再生成空绑定询问。已有接口仍交给原审计器严格比对；不猜来源、不改公式、单位、保护条件。

恢复：只读回放后通过带修订号和预览哈希的恢复接口重验原始提交。保留原报告、问题及格式修复记录；不调用 DSH，不重置额度。当前任务仍已用 1 次、剩余 3 次；三个假问题已清除。另有 resonant_params 依赖列表与实际数据来源不一致，已定位为可局部修正的候选错误，等待使用剩余额度继续。

验证：test_clean_generation、test_submission_protocol、test_binding_repair_receipts 共 33 项通过。未声称完整 LLC 工具生成或数值验证已通过。

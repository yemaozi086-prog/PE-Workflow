## 已实现的边界

新计算契约使用 `contract_version: "3.0"`，新工作流可使用 `schema_version: "3.0"`。所有计算输入、输出为独立命名的 `flat_dict`；字段可以是标量或声明了类型、形状、坐标轴的数值数组。字典不能再嵌套字典。内部函数仍可使用裸参数和嵌套字典，由 `adapter.arguments` 和 `adapter.returns` 显式转换。旧 1.0/2.0 模块、工作流和历史记录继续保留；未批量改写旧模型。

例如电气输入和器件输入分别为 `electrical`、`component`。连接声明 `field_map: {"fs": "f_sw", "i_rms_c1": "current_rms"}`，表示目标字段对应的上游字段。未声明映射时仅查找同名字段，不按大模型置信度猜测。平台检查完整上游数据，再提取下游实际声明的字段；额外字段不会传给函数。映射逐字段检查语义、设备/实例、单位、数组元信息，执行已登记单位换算。试读返回 `connection_plans`，运行 trace 保留实际输入与 `field_mappings`。

转置、重采样、周期截取等仍属于显式变换，需要前提和独立验证样例。新增变量、奖励函数、约束和 PPO 重训练尚未实现，本次没有改变优化算法。

## 对齐词典与扩展规则

`resources/parameter_dictionary-v1.csv` 保留课题组 310 行、14 列原表。导入记录保留原始行、文件摘要、建议声明、问题清单和状态。`quantity` 家族标识、`kind` 方向、设备实例等不被直接混作计算类型。算法控制、路径和配置保留为独立声明，不自动成为计算输入。自然语言单位、配置集合、泛化实例等不能直接判定时标记待复核；引用时必须提供局部语义依据。说明文字不授予文件、网络或代码执行权限。

词典引用为 `catalog_ref: {id, version, name}`。模块冻结完整字段声明，追加词典版本不会就地改变旧模块。`semantic_evidence` 记录人工/任务依据，但平台不能仅凭这段文字证明物理模型正确，仍需要独立样例。

新增 `naming_rules` 是可验证声明，不是可执行正则：支持固定名称和一个 `{index}` 正整数模板，必须提供语义、依据、正例与反例。模块/项目规则通过验证后随模块在同一事务注册；共享推广必须通过单独登记并明确 `confirm_shared`。本地单用户接口中的确认字段是操作约定，不是账号权限系统。规则帮助注册适配，不在运行时静默改名、合并字典或修改接线。

## DSH 对接

- `GET /api/harness/dictionary-contract`：协议 4.0、模块/规则/绑定 schema 和执行边界。
- `POST /api/harness/prepare-registration`：上传源码、模块 ID、指令、已知事实和可选独立样例；返回冻结上下文及 context_id。
- `POST /api/harness/prepare-change`：指定节点的修改上下文，包含上下游接线、词典、规则、原实现和实际基线输入。
- `POST /api/harness/submit-candidate`：提交模块、显式 adapter、anchors、context_id；验证后登记不可变版本。
- `GET /api/parameter-catalogs`、`GET /api/parameter-catalogs/{id}/versions/{version}`：获取词典/问题清单，支持 q 筛选。
- `POST /api/parameter-catalogs`：追加 CSV 版本；`GET/POST /api/naming-rules`：读取/登记规则。

DSH 应先读取上下文，缺少语义集中追问一次，保留公式，优先写显式适配声明；适配无法表达时才生成受控纯计算代码。不可从自己生成的代码复制输出充当独立答案。上下文过期时重新准备，不覆盖原模块。真实 DSH 尚未接入；当前测试使用开发夹具，不能表述为真实智能体自动完成。

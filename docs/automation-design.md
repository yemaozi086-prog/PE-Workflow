# 上传适配自动化设计

状态：Q43–Q50 已确认，首版已实现并完成真实后台闭环。本文保留设计依据；当前实现、验收证据及限制以 automation-guide.md、automation-real-verification.json 为准。持久化实现采用任务表、追加事件表和调度租约表，每次候选保存在事件中，未另建 attempts 表。

## 用户路径

选中节点 → 上传单函数 → 选择“只适配接口/改变模型”并说明意图 → 开始。平台提取源码签名、节点声明、上下游映射、适用范围、词典及可用参考样例。缺少关键单位、语义或验收依据时，界面一次呈现集中问题；不要求用户搬运提示词或 JSON。

界面显示当前阶段、修正次数、待答问题、最近诊断及完成结果。失败报告包含失败阶段、具体字段/样例、预期与实际、已尝试变更、仍缺的依据。模型对根因的推测必须与平台实测事实分开。用户可补资料后继续；明确批准可增加修正预算。

## 调度权与智能体能力

平台持有状态机，决定何时生成、验证和应用；不让 DSH 自由选择发布步骤。首版一个计算代理完成语义审查、适配生成与诊断修正，通过阶段指令切换职责，不需要多智能体协商。

新增独立 `flux-worker` preset，保留现有手动 `flux` preset。worker 仅具有读取当前任务冻结上下文、提交一次结构化澄清、提交候选的工具。禁止登记模块、保存工作流、应用修改和启动优化；不得提供任意 HTTP、文件读取或命令执行工具。上传代码只是数据，候选只在平台受控计算进程中执行。worker 不可读取评估端隐藏样例或参考适配器。

能力分为明确的阶段：

1. 语义审查：输出已确认映射及依据、缺失关键项；不能自行决定新物理口径。
2. 候选生成：输出单函数源码、入口、扁平字典声明、显式 adapter、必要的局部命名规则及变更解释。
3. 诊断修正：根据平台错误、上一候选及允许修改范围产出新候选；不能改验收答案、放宽契约或填零掩盖失败。

这三类输出均须有 schema。解释文字不驱动发布，结构化候选才进入验证。上下文包括任务/调用/尝试编号、源码摘要、目标节点路径及版本、原模块与 adapter、上下游声明、已知事实与用户回答、类别、验收依据、数值库白名单、禁止变更项、上次诊断和候选差异。词典按相关字段筛选，必要时受控检索，避免每轮无差别堆入全部资料。

## 本机 DSH 接口证据

已检查本机源码 `D:/deepseek-harness-master/deepseek-harness-latest`：

- `packages/host/apiproxy/src/api/sessions.schema.ts`：session.create 支持 sessionId、agentPreset、cwd/workspaceId；session.prompt 支持 sessionId、queue/steer、文本 content。
- `apps/web/tests/smoke-real.e2e.ts`：通过 POST `/api/session.create`、`/api/session.prompt`、`/api/session.history` 调用，信封为 `{type:"client-request",rpcId,method,payload}`，结果为 `result.ok/value/error`。

因此设计为平台后台通过本机 3080 RPC 创建专用 worker 会话并提交阶段任务，使用历史读取核对请求及状态，worker 回传候选/澄清到任务专属接口。无需浏览器自动输入，不在 PE-Workflow 保存模型 API Key。上述是源码支持，尚未验证自动调度端到端。实现前需核对当前服务鉴权、历史分页/事件游标、完成/中断事件以及 prompt 送达判定；不能把 rpcId 的存在当作服务器保证去重。

## 状态与持久化

建议独立 automation_tasks、automation_attempts、automation_events，复用现有 change_tasks 作为验收/原子应用基础，不把后台执行塞进 HTTP 请求或内存定时器。

状态依次为分析、等待澄清、等待验收依据、等待 DSH、验证、修正、准备应用、已应用；异常分为需要重新检查版本、重试预算耗尽、连接状态不明和基础设施失败。每次转换持久化事件、输入摘要与输出引用。候选及诊断不可覆盖。

每个任务保存 workflow_id/revision、目标完整节点路径、模块版本、源码摘要、context_id、DSH session_id、调用编号、尝试序号、修正预算、执行租约及最后核对位置。请求发送前记录意图，送达/候选接收后记录结果；数据库事务不跨越模型等待时间。

worker 使用任务/尝试绑定的短期随机凭证，只能读自身上下文及提交本轮结果。重复回调以调用编号和内容摘要幂等处理；过期或跨任务结果不能应用。同编号不同内容报冲突并保留诊断。通用手动写接口仍是本机受信边界，专用 worker 不获得调用能力；这不是操作系统级隔离保证。

## 验收与发布

只适配接口：使用冻结原模型的已知有效输入输出作为回归依据，并保留评估端隐藏工况；只证明所覆盖范围内等价。改变模型：新的公式/口径和独立样例不足则等待补充，旧结果仅用于声明未改部分。平台不得用候选自身输出制造答案，也不能靠 AST 差异完全证明公式没变。

候选经过声明/语法/库边界检查、语义及单位/数组检查、锚点回归、目标替换后的完整图试读和试运行。候选验证不提前登记公开版本。全部通过后使用已有原子应用事务发布模块版本、工作流修订及运行记录；失败保留旧图。首次真实验收不允许人工手改候选，只能补答信息，由 DSH 修正。

工作流版本改变时先停止发布，获取最新图并展示差异：无关布局等变化可重新验证；目标节点、公式意图或验收依据改变则等待用户澄清。无论哪种情况，旧验证结论都不能直接复用。应用事务再次检查版本，重复应用返回同一发布结果。

## 修正、续试和恢复

首版预算定义为“初次生成 + 最多 3 次修正”，不把网络传输重试计作候选修正。相同错误按验证阶段、错误码、目标字段/样例位置归类；同类连续两份候选仍失败则提前停下。不同字段上的同一通用错误码不能简单视为重复。缺少语义或独立答案不属于可循环修复错误。

暂停报告保留具体失败、候选差异及下一步所需信息。用户批准后追加最多 3 次修正，创建新的预算批次，保留之前历史与失败原因；新批次重新计连续失败，防止批准后立即被旧计数挡住。用户不能通过追加预算绕过关键证据门槛。

重启后恢复未完成任务：先核对平台发布记录、DSH 会话与调用历史。已完成验证/发布不重复执行；已送达且仍执行则重新观察；发送结果不明且无法核实则等待用户选择重试。不会以超时推断模型未收到请求。失效租约可恢复调度，但不能直接重发模型请求。迟到候选需匹配当前尝试编号，不能覆盖新尝试。

## 实施与验收顺序

1. 增加状态/事件/尝试持久化和可重复验证接口；先用可控模拟 worker 验证正常、澄清、修正、停止、续试、版本冲突、重复/迟到回调和中断恢复。
2. 增加专用 preset、DSH RPC 适配和任务凭证，验证真实后台创建、提交、结果回传及中断核对。
3. 前端提供上传入口、类别选择、问题卡片、进度与失败续试；不暴露内部工具调度给研究人员操作。
4. 用未提供参考适配器的电容接口变体做真实闭环；保存全部调用、候选、诊断和数值结果。仅通过模拟 worker 不能宣称真实 DSH 验收完成。

首版不扩充 PPO、多目标配置、任意复杂 Python 或多人部署。

# 旧项目迁移边界

旧代码与运行数据没有被修改。本项目不依赖旧项目服务、全局工程、归档目录或缓存才能运行。

## 已迁入

- `user_igbt_loss_temp_v1/module.py` 的简化损耗关系：`P_cond = Vce(Tj) × I_rms × 0.5`、`P_sw = E_sw × fs`、`Vce(Tj) = Vce + 0.0018 × (Tj-25)`。新模块族为 `switch_loss`，v1 基线、v2 结温演示；旧模块实现本身未被改写。
- 字段级契约、显式单位换算、模块派生、锚点回归、工程版本与运行取证的设计经验。
- 将旧平台里“优化器必须读到用户修改后的工作流”的教训变成冻结工作流/模块/输入的一体化运行快照。

## 逐项迁移顺序

1. 从固定 DBSRC/DAB 环境选定输入与中间结果，建立与画布无关的基准夹具。
2. 电压/电流模型：写纯计算适配器，把实际输出声明完整；不能从选型汇总表推断损耗所需的逐管工况。
3. 器件选型与器件数据：确定可序列化数据合同，避免把带副作用的 Python 对象塞进运行状态。
4. 详细开关、变压器、电感与电容损耗，以及逐器件约束：逐个对齐基准，不用零值占位。
5. 多工况指标及标量奖励：明确 max/mean/weighted 的口径，独立声明归一化和不可行判据。
6. 补齐优化任务的变量、约束和多目标协议，再考虑 PPO。

完整旧代码包含类、SciPy 求解和器件库，不属于当前上传 Python 子集。迁移应通过审计过的受信 provider/适配器扩充后端，而不是放开外部代码的任意执行。

每个迁移项的验收至少包括：固定输入的中间值/最终值对照、错误输入、声明与实际字典字段一致性、快照回放。不能只检查“流程运行完成”。

# 从零生成与通用机制验收决策

## 已确认（2026-10-20）

1. 优先修复通用生成机制，再在隔离的干净数据环境从零生成原 LLC；不以继续修补当前任务作为验收。理由：已解决的问题必须使后续任务受益。
2. 验收覆盖原 LLC 和一个结构不同、包含分支与有限循环的新任务；不得由开发助手手改模型候选来取得通过。理由：同时验证完整链路和跨任务适用性，不把一次成功外推为所有任务成功。
3. 先完成无需模型的检查，之后做限额真实 DSH 验收。每阶段首次生成加最多三次修正，同类错误连续两次停止；追加调用需要明确批准。理由：提供真实证据，同时避免无限重试与隐性预算重置。
4. 平台测试、从零生成、独立数值验证分别报告；任何一层通过不能替代另一层。

5. 干净环境保留通用平台、公共工具、标准与自定义单位表、已修复的 DSH 协议；排除 LLC 专用工具、任务、候选和历史对话。使用原提示词，不附加 LLC 接线答案。理由：检验正常新任务体验并排除旧结果依赖。
6. 开发者依据冻结公式独立准备正常、边界与不适用工况的参考计算；预期结果不提供给生成候选的 DSH，只交给验证器。参考实现不能复制候选代码，不能为迎合候选而修改答案。理由：验证代码符合声明模型；不将其宣传为实验或仿真验证。

# 平台检查分级

目标：平台负责可确定的协议与执行约束，智能体负责实现，人负责工程含义、验收依据和发布决定。不能把每个提示都升级为阻断。

| 分类 | 例子 | 行为 |
|---|---|---|
| 阻止或按证据修复 | 未声明字段读取、无缺省/保护的可选字段读取、非法语法、字段类型/单位冲突、不合法来源作用域 | 定位问题；明确代码错误才按原额度局部修复 |
| 提醒 | 声明为必填但当前代码和保护条件未使用 | 保留契约继续检查，报告冗余字段；不要求 dummy 读取，不默认代码完整 |
| 待确认 | 公式、物理来源、接口、保护条件、单位定义或独立样例冲突 | 展示证据和差异；不能静默改动 |
| 平台自动处理 | 已有精确证据的无损信封适配、明确绑定的确定性组装、检查与记录 | 不调用模型重复抄写内容，不冒充工程验证 |

`required` 只规定调用时必须提供。冗余不会自动改变其值，也不会自动移除字段。optional 仍必须由代码安全处理缺失；新规则没有把不安全读取降为提示。

方案阶段集中检查声明合法性，计数单位冲突和空字段语义提前暴露。未登记单位作为可处理提醒保留现有扩展入口，生成代码前必须按既有流程确认。没有实现代码时，不解析 LaTeX 猜测最小字段，更不据此删除接口。

旧 `INPUT_USAGE_REVIEW_REQUIRED` 暂停项在批量恢复清单中显示“复检原候选”。用户确认后使用原代码、接口、检查和样例重新验证，不调用模型、不重置额度或重复错误计数，不注册工具或运行工作流。发现真实问题仍停止或分流。代码是否完成了物理要求，必须对照公式、输出和独立验证，字段读取本身不能证明。

界面区分待补声明（未调用）、原候选可复检、接口待确认、代码问题、平台问题和额度耗尽。输入冗余以提醒显示；工程验证状态继续单独呈现。

# 规划协议与生成效率优化：决策记录

## 已确认（2026-10-19）

1. 同时补齐计算方案的循环/子图声明及简化输入协议，由程序构造正式契约，再以LLC验收。理由：执行引擎有控制节点，但平铺规划协议不能充分表达它们；仅补数组示例无法解决端到端问题。
2. 程序只补可确定的格式及复用明确声明。维数、轴语义、单位、遍历方式必须有依据；缺失或冲突时集中询问。理由：减少机械填充，不引入物理猜测或把动态长度硬编码成21。
3. 原LLC任务、失败与额度记录保留。新协议完成后派生修订、展示差异，经用户确认后继续，不自动追加模型额度。讨论不擅自停止在途调用。理由：避免新旧协议混用和隐藏重试。

沿用此前已确认边界：平台故障不能靠改候选绕过；公式与样例冲突需用户确认；所有模型调用计入既有额度；改变已确认公式、接口或约束需派生确认；未验证与语义缺失分开处理。

4. 首次完整生成，后续以哈希绑定局部修改为主。格式补丁不得改变公式、拓扑、单位、语义、必填性或默认值；接口来源修复复用现有PlanPatch。无法限定修改范围时停止并要求核对结构修订。理由：缩小输出与回退风险，不让格式修复变成重新设计。
5. 展示可观察事件耗时；长等待阈值可配置，只提示检查/停止，不自动重发或声称远端已取消。工具读取及心跳不等于有效结果进展。理由：避免重复工作，明确进度证据边界。
6. 第一版支持有限一维数值轴笛卡尔积与单层batch子图，可多个独立或前后相接的有限控制节点；不承诺嵌套、收敛或任意拓扑。使用LLC与非LLC任务、非法输入及无候选情况验收。理由：满足当前演示并检验控制逻辑可复用，不靠LLC专用执行器。

## 实施与验收范围

- 新任务使用简化blueprint：接口定义一次，多处引用；数组形状、轴名、dtype显式声明，程序构造冗余底层字段。
- 原任务不自动采用新协议，不自动重试；迁移预览→明确派生→按剩余额度继续，耗尽时另行批准。
- 自动化LLC核算使用测试专用模块，不注册到用户工具库、不冒充DSH生成；真实DSH端到端预演须迁移后另行核对。

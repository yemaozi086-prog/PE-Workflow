# 方案接线预检查与重新生成

在“从需求设计工作流”中打开已有方案。若显示“方案还不能直接接线”，先点“根据需求与诊断重新生成方案”。

在需求文本中保留公式、物理含义、适用前提和希望输出的结果；若原文包含测试答案，可以删除答案后再提交。平台不会替用户修改原始需求。提交会调用智能体，创建派生方案，保留原方案、历史和模块版本。

新方案应清楚显示每个字典的来源：外部输入，或某一步的输出。一个字典端口只能有一个来源。字段改名使用同一来源内部的显式映射；不能靠一段文字把上游电流和外部电阻自动合并成同一个字典。需要多个来源时，提出接收多个独立字典的新工具，用户确认后再生成、验证和注册；原工具不覆盖。

例如损耗工具可接收 `electrical`（上游 RMS 电流）与 `device`（外部电阻），汇总工具可分别接收各损耗字典。RMS 电流须保留 `statistic=rms`，损耗的 `quantity` 应与输出工具一致，不能删除声明来绕过校验。

## 声明格式

`DesignStep.derives_from` 标记需要派生接口的旧工具（此时 `module_ref=null`）；注册时分配同一工具的新版本并记录父版本。`DesignPlan.external_inputs` 声明运行时外部字典；`DesignStep.input_sources` 使用工作流同样的 `Binding`。`field_map` 方向为目标字段名到来源字段名。运行数值在运行时填写，方案不植入默认值。

`DesignStep.input_checks` 声明计算前执行的条件，例如 `design['L'] > 0`。条件只允许字段、常量、比较与逻辑运算，不允许函数调用或除法。可使用 `operating['Vin'] > operating['Vout'] and operating['Vout'] > 0` 等用户明确给出的前提。依赖上一节点的条件，如 `current['Imin'] > 0`，放在首次使用该结果的下游节点之前。绑定阶段原样保存到 `Node.input_checks`；不满足时以 `INPUT_PRECONDITION` 停止，保留失败节点和条件，不返回伪造的结果。

平台校验每条显式来源的字段、单位和语义，并核对依赖关系。无法接线的方案不会进入工具生成或工作流拼接。旧版独立单步方案仍可使用；旧版有依赖但未声明来源的方案需要重新分析。已经保存的工作流和历史记录保持不变。

这些检查不证明物理模型正确，也不能自动证明全部除法、开方等运算都有充分保护。智能体须根据用户声明提出前提，用户确认后再通过合法和非法边界样例验证。工具独立测试与整条计算链的运行测试仍是两回事。

## 自动修复反馈

预检查的 `repairs` 随 `plan_repair`、失败报告和派生任务上下文提供给 DSH。端口缺字段时，列出已满足字段、缺失字段、已声明且类型／单位／语义兼容的候选来源，并给出接口派生的修改要求。候选列表不代表已经选定器件；物理角色由用户公式或已有证据确定，无法确定就追问。

接口拆分后，保护条件也必须改用节点的局部输入名。平台按明确的 `input_sources` 和 `field_map` 列出可对应的局部路径，不修改原条件，不删除保护。不同错误使用具体错误代码和路径分类；缺字段已经解决、转为保护路径错误时，不再仅因都属于预检查失败就算作同一个重复错误。同类错误连续两次及总调用上限仍然生效。

修复建议由智能体实现并重新接受平台检查，平台不直接改写候选、合并字典、生成验收答案或覆盖模块版本。

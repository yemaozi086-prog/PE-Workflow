# DSH 契约闭环与真实验收

日期：2026-10-20。本轮依据上一轮复查发现继续实施，不以“已有测试通过”等同于真实首次生成成功。

## 1. 候选已收到后的平台处理

候选回执继续在解析前持久保存。当前单进程本地服务为每个调用维护在处理请求的所有权；同一调用的并发重复提交被拒绝。不能因为校验时间长就认定中断。

没有存活处理请求而有未处理回执时，标记 CANDIDATE_PROCESSING_INTERRUPTED：界面显示“候选已收到，但平台校验中断”，提供“复检已收到的候选（不调用模型）”。不会给 DSH 再发一次生成要求，不会增加调用次数，不会自动注册或发布。

复检使用原回执和当前校验链路，保留原文。检查通过后进入核对；检查失败则按证据分流，但本次复检不自动调度模型。多份未处理回执须明确选择，不猜选。已有候选、用户停止、归档、派生和版本锁仍有效。

此所有权机制针对当前一服务进程部署；若未来多实例部署，必须替换为跨进程的持久租约，不能直接依赖进程内锁。

## 2. 首次规范与检查器共源

受控解释器发布 syntax_manifest，直接读取实际 AST、运算符、语句、允许导入、函数目录和预算定义；相同预算常量用于真正执行校验。首次 rules 同时给出数组布尔掩码的受支持写法、禁止形式、显式变换和验证材料要求，不再等待第一次失败才提供。

专项执行示例覆盖标量表达式、受支持数组掩码、禁止的位运算和列表推导、未登记函数及关键字，并验证调整预算常量时清单和实际拒绝行为同步。

发现并修复 Schema 传输缺陷：原分页压缩会删除空对象，导致 delta 的 value:{} 定义从 properties 消失，required 却仍要求 value。Schema 章节现在无损序列化并分页，完整重组必须等于原 Schema。

## 3. 两次真实 DSH 测试：真实失败，不报喜

在独立数据库和独立本地 HTTP 服务中测试“固定电阻焦耳损耗的有限电流扫描”。使用预先声明的 ohmic_loss@1；每次仅允许1次规划调用，不追加，不注册、不发布到生产平台，独立数值答案不提供给 DSH。

两次均35秒左右返回同一问题：循环输出写成 loss.p_w 的字段抽取，而平台 batch 要求完整 loss 字典。实际任务：

- e58fa949d9a445bfa6daa65e3378e5bb
- d87cf4d66743424188bea5b7e76ab2c8

首轮端到端通过率为0/2。按同错两次停止，不继续追加测试，原始结果保留在 data/protocol-audit-20261020/real-scan-20261020/report.json 和该目录独立数据库中。

这揭示了两层平台问题：首次 PlanLoop.outputs 仍复用了允许 field 的通用 Binding Schema；错误分流在步骤省略已注册接口时，未使用冻结模块声明，误把可确定的修正判为需要用户补充来源。

## 4. 根据真实失败修正

- PlanLoop.outputs 的 Schema 现在明确要求 source=node、node、port，禁止 field 标量抽取、常量和字段映射。
- 分流从所选精确注册模块查字段，确定性结构修正不再产生物理来源追问。
- 对已明确成员节点、输出端口及存在字段的情况，平台在原文之外生成审计规范化：去掉字段抽取，保留原别名、节点、端口、公式和字典内原字段。方案仍需用户确认。
- 字段未知、来源节点未知或存在字段映射时，不执行这项规范化。
- 原回执固定为 backend/tests/fixtures/real_scan_scalar_output.json，测试原回执经新版真实平台处理链可一次进入 awaiting_confirmation、calls=1，原回执原文不变。
- 在隔离副本上验证限定补丁，经严格契约、接线和执行器得到 [0,0.5,2,4.5] W（电流[0,1,2,3] A，R=0.5 ohm）。这属于平台回放和数值回归，不能记为 DSH 修复后重测成功。

## 5. 验证边界与后续

本轮真实模型调用总共2次，均发生在发现上述新缺陷之前。修复后做了原回执回放、受限修正验证和反例测试，没有再调用真实模型。因而不能报告新的 DSH 首轮通过率，也不证明完整 LLC 已重建成功。

后续真实验收应冻结平台/模型/提示词版本，在新隔离库分别覆盖单点、有限扫描、LLC及另一条计算链，保留固定额度并分别统计：首轮协议通过率、限额内完成率、平台错误、信息补充、真实不支持能力和无法恢复状态。不要混合“平台回放通过”“模型重新生成通过”“工程数值验证通过”三种证据。

当前自然语言规划范围仍是一层有限 batch 与显式网格；嵌套和收敛迭代规划没有在本轮扩展。

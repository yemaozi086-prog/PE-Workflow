# 已声明来源的接口形状修复

本次解决旧 plan_patch 只允许字典拆分/改名，却把循环输出数组的必要修复拒绝的问题。

- 普通补丁仍冻结接口字段声明。只有显式 repair_shapes=true 的编辑可以修正 type、value_type 和 axes。
- 平台按已确认 input_sources 和 field_map，读取当前作用域的正式来源；不猜物理来源，不改字段集合、单位、语义、必填性、默认值、公式、输出、计算依赖或保护条件。
- registered 模块须 derive_interface=true，原版本保持不变；待补工具无需伪造派生来源。
- 保护条件不能用于数组时照常拒绝，不能删除保护来通过。未解析控制契约或未知来源不自动修复。
- GET shape-repair-preview 不写任务、不调用模型。返回逐字段差异、来源、修订号、补丁哈希及全方案检查结果。
- POST shape-repair-confirm 仅接受匹配修订和哈希的预览，经用户确认派生新方案，原记录、已用次数、上限、重复错误限制保留；重复提交返回同一修订。
- 结构检查不证明数值或工程正确性，不注册工具、不运行。
- 提交包装层在模型解析前拒绝字符串/数组形式的候选，精确指出 /patch 等路径；不猜测或解析损坏字符串。原始提交继续保留。

当前 LLC 68277e 的只读复检：在 case_results_assembly 定位 24 项形状/轴差异，按正式来源修复后全方案接线检查通过。未将修正写入生产任务，未追加 DSH 次数。

# 受控公式工具开发闭环

本次仅覆盖公式生成阶段，不新增 MCP。已确认方案、物理假设、单位、字段必填性、保护条件、注册与发布审核继续由平台和工程师管理。

## 提交内容

新公式调用在正常 dispatch 时启用 `formula_code_v1`。DSH 按需读取当前步骤与公式、实际解释器语法和紧凑提交 schema，仅编写 `FormulaCode`：实现类型、源码或表达式、显式适配与变换声明。输入输出、单位、保护条件、项目、名称和不可变版本由平台从已确认步骤装配；不能在实现提交中修改这些信息。

旧调用保持原完整 Module 协议。新调用只接收带最新通过预检回执的 `module_code`，不能交一份完整 Module 绕过预检。

## 同一调用内预检

`design_precheck` 经现有任务绑定桥接到 `POST /api/workflow-designs/{id}/formula-precheck`。它调用与正式提交相同的 `check_formula_candidate`，检查接口、受控语法、字段/保护依赖、已提供的独立样例及最小/额外字段测试。没有独立样例时不声称运行或数值验证通过。

每次模型调用最多预检 3 次，单次检查最多 60 秒，累计最多 120 秒；同类错误两次停止。预检次数与模型调用次数分别显示，不追加原模型额度，也不在用户补充后静默重置模型额度。预检仍消耗本次会话的推理和工具时间。

明确代码错误允许局部修正。受控解释器明确拒绝布尔/字符串算术等错误可返回候选修正证据；成功执行但不符合独立答案不能据此判断代码一定有错，保留实际结果并暂停核对。进程启动、通信、超时等平台故障不得通过修改公式修复。

预检成功仍不注册、不发布、不运行完整工作流。最终提交必须匹配本调用最新通过的代码哈希和契约哈希；平台再次调用相同校验管线，随后进入原有候选人工核对与注册入口。

## design.n 等未使用字段

访问检查不是公式完整性的证明。未使用字段触发原有输入依赖修订核对：代码漏实现应修代码；原契约多声明了字段才提出接口差异；用于保护的字段保留。平台不会自动删字段、改必填性或添加假读取。

## 恢复与审查

预检日志独立保存在 `formula_prechecks` 表，不污染正式候选回执。任务暂停、切换、归档或契约变化会使在途结果失效；迟到正式提交沿用旧回执隔离机制。平台重启后的原预检记录和消耗不会丢失，同一调用中断不重发；新调用仍须沿用原阶段剩余模型额度。

界面显示当前预检次数、检查/修正/暂停状态，并可按需查看代码及逐次诊断。日志不包含独立预期答案；答案冲突仍仅在用户验证反馈区域显示。

## 验收

定向测试覆盖预检到正式候选/人工注册、同轮语法修正、重复错误停止、剩余额度不变、鉴权、过期回执、代码变更、暂停并发、未使用与仅保护字段、独立答案隔离、运行时错误分流、紧凑上下文及真实 Node 工具封装。

`scripts/verify_formula_authoring.py --run-real` 是显式选择的真实 DSH 验收：工程师给定的电阻损耗步骤通过公开修订和队列入口进入公式生成，最多一次模型调用、三次预检，使用真正的派发、回调桥和受控计算子进程。只用独立数据库，不注册、不发布、不改生产任务；它不能替代完整 LLC 生成和工程验证。

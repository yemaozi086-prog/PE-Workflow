# DSH 提交链路修复（2026-10-20）

## 已观察的故障

排序修复会话先后提交了七次 JSON 语法不完整的工具参数。DSH 将无法解析的参数作为字符串交给工具；旧工具没有顶层类型检查，Python 桥接直接调用 `.pop`，返回缺乏定位意义的属性异常。最后一次参数 JSON 可解析，但 module 仍是字符串，且内部 JSON 不完整，因此平台拒绝并保留原始提交。

此前本地 JS 单元测试只覆盖对象参数中的字符串模块，没有覆盖整个工具参数为字符串的真实输入形态。磁盘预设一致也不足以证明长时间运行的 DSH 进程已重载相同文件路径的插件。

## 修复

1. JS 工具和 Python 桥接各自验证顶层参数为对象；畸形文本、数组、null 不进入提交路径，返回结构化诊断和停止指示。不自动解析或修补候选。
2. 保留模块必须为对象、source 必须位于模块根部的检查和有限格式修正规则。
3. 安装器按工具源码 SHA-256 生成唯一 JS 文件名，并在安装后的 agent.cordis.yml 引用该文件。新会话使用新的导入路径，避免同路径模块缓存；重复安装同版本保持幂等。
4. 工具初始化时捕获自身指纹，桥接核对该指纹与项目源码。旧运行时或未携带指纹的设计工具在发送 HTTP 前被拒绝。模型参数不能替代工具附加的真实指纹。
5. 对 DSH 以字符串传入、且仅缺少末尾根对象闭合花括号的工具参数，JS 工具只做有界的尾随花括号补齐后按 JSON 对象提交；若缺括号导致已知的 module.outputs/source 被错误嵌进 module.inputs，只把这两个包装成员移回 module 根，不改源码、端口或元数据。合法 JSON 字符串、候选内部字符串和其他畸形仍拒绝。
6. 平台冻结配置记录实际渲染后的预设文本，并在调度前核对安装文件及指纹。

## 验证范围

- 安装后的 JS 插件 → 实际 Python 子进程 → 本地 HTTP → 平台真实候选校验。
- 错误顶层参数、字符串模块、过期运行时、Unicode 多行代码、嵌套引号和较大 JSON。
- 合法候选通过独立算术样例成为待核对候选；代码无损，调用次数不变，不注册、不运行真实工作流。
- 不调用真实模型，不修改现有排序候选，不增加其额度。传输测试通过不代表排序算法或 LLC 模型通过验收。

主要验证入口：`node scripts/test_design_submit.cjs`；`backend/tests/test_design_transport.py`；`backend/tests/test_design_bridge.py`；`backend/tests/test_preset_installation.py`。

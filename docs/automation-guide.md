# 自动上传适配：使用与验收

已实现本地 Windows 单机的自动化闭环，2026-10-15 已通过真实 DSH 验收。设计见 automation-design.md；具体证据见 automation-real-verification.json。

## 使用

1. 确保 DSH 在本机 3080 运行、PE-Workflow 在 8020 运行。专用 worker 已安装；重装命令为 `node scripts/install_flux_worker.cjs`，不会改变默认 preset 或旧 pe-agent。模型及 API Key 仍由 DSH 管理。
2. 打开工作流，选中 v3 字典计算节点，在属性中点击“上传并自动适配”。
3. 上传单个 .py 纯计算函数，选择“只适配接口”或“改变模型”，说明意图；可填写已知单位/参数口径。
4. 点击开始后无需进入 DSH 对话或搬运 JSON。平台创建 worker 会话、发送上下文、接收候选并推进验证。关闭弹窗不会取消任务，重新打开后可恢复持久化任务。
5. 如需补充语义，集中回答问题；改变模型需要至少两组独立输入/预期输出样例，不能从候选自身取得答案。
6. 候选、样例和完整图通过后自动发布新模块和新工作流版本；“查看已发布结果”将结果加载到画布。

只适配接口时，平台从冻结旧工作流提取目标节点真实输入/输出，并在声明允许范围内尝试一个邻近输入点，生成至少两组旧模型参考。无法取得足够有效样例时停止并请求依据。这些只证明所覆盖范围内的等价，不证明原模型真实物理准确性。

## 失败处理

初次生成后最多修正 3 次；同一阶段、错误码、字段/样例位置连续失败两次则提前停止。schema 错误也保存为候选诊断，由平台发起修正；不会让 DSH 自行跳过校验。每次候选、结果与状态转换在 SQLite 中留档。

界面展示失败阶段、错误码、具体信息和原始验收报告。智能体解释单独展示，不能替代实测诊断。点击“批准继续”追加最多 3 次修正，保留之前历史；关键依据缺失时只能先补充资料，不能直接续试。

工作流变化时保留候选并阻止发布；批准重新检查后获取最新版本。目标节点自身改变时要求根据新目标创建任务。模型请求送达状态不明时不自动重发；用户明确批准重试后才开始新调用，并提示可能重复产生费用。旧调用的迟到结果不能覆盖新调用。

后台通过租约保持一个调度者，任务更新使用比较并交换。重启后核对任务和 DSH 历史；已完成发布不重做。实际应用复用 change-task 的幂等与原子提交，模型等待期间不持有数据库事务。

## 智能体边界

独立 flux-worker preset 仅有 `flux_worker_context`、`flux_worker_result` 两个工具。每轮任务凭证绑定 task_id/call_id，过期调用不能读新任务或覆盖新结果。worker 没有注册、发布、运行、文件读取、命令执行和任意 HTTP 工具；现有手动 flux preset 保留用于调试。

新任务默认使用 `implementation_patch_v1`：在 `flux_worker_result` 顶层提交 `patch`（代码、入口、适配映射、来源说明和授权的新输入名称），不得提交 `module` 或复制原端口声明。平台从冻结契约组装候选再执行全部验证。DSH worker preset 使用 `flux-worker-tools-patch-v1.js` 入口，安装时应复制整个 preset 目录。协议边界与真实效率验收见 [受限实现补丁协议](implementation-patch-protocol.md)。

上传原函数必须保持不变，参数名、路径、组装、单位和返回值差异通过 adapter 处理。需要修改源函数才能支持的复杂程序当前会被拒绝；本轮没有扩展任意 Python 执行能力。任务可以携带显式新增绑定，但首版 UI 主要面向保持现有外部字典契约的单函数替换；新增变量/目标/奖励配置与 PPO 重训练仍未接入。

## 首次真实验收

输入：examples/automation-capacitor/uploaded_function.py 与 facts.txt。函数使用 MHz、uF、嵌套参数和元组返回，返回 W/mW 两种单位。没有向 DSH 提供参考 adapter，也没有人工修改候选。

- 平台主动创建专用 DSH 会话，真实记录中的工具调用仅有读取上下文、提交候选。
- 首次候选通过，修正次数 0；发布 cr_loss_flat@2、dictionary_capacitor_demo r1。
- 基准结果：loss.cap1_loss、loss.p_cap_total 均为 1.1368210220849666 W。
- 另有 4 组未送给 DSH 的工况与旧模型一致。
- 完整后端测试 112 项通过，包含自动化相关 15 项；前端生产构建通过。
- 已在浏览器恢复已完成任务并查看发布结果。

真实验收证明的是该接口变体的自动适配闭环。自动修正、澄清、预算、租约、冲突与恢复分支已有程序测试；没有将它们全部宣称为真实模型逐项验收。

当前为本机受信应用，无多人鉴权或公网部署能力。任务超时后会阻止迟到结果应用，但不会保证 DSH 已停止推理。后台采用轮询读取状态，暂不提供实时 token 展示或自动费用估算。


### 2026-10-15 版本冲突修复

示例入口已有保存版本时优先加载最新修订，不再把初始模板当作 r0 草稿。自动准备在任何计算前检查版本冲突，完整错误记录到事件中。版本更新按钮显示工作流和目标模块版本差异；只有用户明确确认后才读最新目标重新准备，同模块族版本变化可以确认，接线/结构变化仍要求新任务。界面 DSH 调用次数与本地续试次数分开，准备失败不算模型调用。


### 等待进度和重复上传

生成期间显示调用等待时长，后台约每 15 秒读取任务专属 DSH 历史，只记录事件类型/数量等摘要，不展示模型内部推理或凭证。重复上传当前同一函数（接口适配、无新增事实/绑定）会显示“已有相同实现，无需替换”，不再生成或发布。已在运行的已确认重复任务可以取消其专属 DSH 调用，保留已有成功结果。A 已实际发布为 cr_loss_flat@3、工作流 r2；后续澄清实验应上传 B，而不是再次上传 A。


### blocked 后补充依据

集中追问后的 blocked 结果可能没有新的问题字段。此时可只填写新增确认依据，不再要求重复回答上一轮的问题。前端不提交已失效的回答字段；历史回答继续留档，worker 上下文单独标出最新用户补充。空补充或原样重复未知回答会保持 blocked，不视为已确认。上传前显示目标节点名称及输入输出摘要；更换模型职责须重新选择正确节点创建任务，补充单位不能改变原任务的目标。

# 受限实现补丁协议

新自动适配任务默认 `worker_protocol=implementation_patch_v1`；旧任务未声明协议时仍按完整模块协议读取。DSH 只提交顶层 `patch`，不能用 `module` 包装补丁。

补丁允许字段：`source`、`entrypoint`、`adapter`、`provenance`、可选 `description`、`added_inputs`（名称列表）。禁止身份、版本、输入输出契约、可信内置标识等字段。新增输入名单必须与冻结授权的端口名单完全相等，不能覆盖原端口。

平台从任务冻结的 base_module 复制所有原契约，复制已授权的新端口，分配新版本并记录真实父版本，切换为受控 Python 实现。源码原文保留，不替智能体修正代码。随后执行原有语法、映射、单位、数值样例、完整工作流及所有验收工况检查，通过后才原子发布；越界、参考不符或版本冲突均不会覆盖旧流程。

若要改变原字段的单位、物理含义或下游契约，需要另行说明影响并取得授权；当前补丁不能表达此类操作。`module_v1` 仅用于已有客户端兼容，DSH 不能通过任务工具切换冻结协议。

发送给模型的任务包去除整图、完整注册表及重复 JSON Schema；保留目标接口、受控数值函数清单、授权端口、独立样例、有限代表样本、诊断及上次补丁。完整证据仍冻结在平台。上下文大小比较采用同一任务分别构造两种协议的 UTF-8 JSON，避免把场景差异当成优化效果。

测试覆盖：正常发布、原声明保持、越权字段拒绝、未授权输入拒绝、错误参考结果不发布、误用旧 envelope 明确报错、实际路径与单位换算、旧任务回放兼容。

真实验收使用原 v1 独立副本 `dbsrc_patch_efficiency`，不覆盖已有 DBSRC r2。仍采用三温度参考、相同停止规则，候选不人工修改。结果记录在 `patch-thermal-verification.json` 和 `patch-efficiency-report.json`；运行结束前不得宣称数值验收或效率目标通过。
